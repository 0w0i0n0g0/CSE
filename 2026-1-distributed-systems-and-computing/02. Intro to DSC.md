## 01. Intro to Distributed Systems and Computing

### 1. 분산 시스템의 5가지 유형

- **High Throughput Computing**: 웹 클릭처럼 수많은 사용자가 접근하여 초당 처리 개수(스루풋)가 많은 스케일러블한 시스템.

- **Big Data Computing (High Performance Computing)**: 처리량이 방대한 시스템. 스루풋은 적지만 작업 하나를 오랜 기간(예: AI 연산) 수행하는 데 사용됨.

- **GPU**: 병렬 처리를 수행하는 컴퓨터 시스템.

- **System of Systems**: 위의 시스템들이 결합하여 이루어진 거대한 시스템.

- **P2P 시스템 (예: 비트코인)**: 중앙 서버 없이 노드 간 연결되어 중단되지 않는(Fault-tolerant) 시스템.

> 하둡(Hadoop) 2.0은 개념적으로 다루지만, 이번 학기의 핵심은 **도커(Docker)와 쿠버네티스(Kubernetes)**.

---

### 2. 분산 시스템을 사용하는 이유와 목표

- **자원 공유(Resource Sharing)**: 초창기 인터넷 환경에서 프린터 등 하드웨어나 데이터를 내부 네트워크를 통해 공유하기 위함.
- **연산 속도 향상(Computational Speedup)**: GPU처럼 여러 자원을 동시에 사용하여 연산 속도를 높이기 위함.
- **안정성/신뢰성(Reliability)**: 컴퓨터 한 대가 고장 나도 시스템이 중단되지 않도록(No Single Point of Failure) 다수 기기를 운영.
- **통신(Communication)**: IP나 포트 번호 등 하위 계층을 고려하지 않고도 데이터를 주고받을 수 있는 통신 인프라 구축.
- **주요 목표**: 투명성(Transparency), 개방성(Openness), 확장성(Scalability), 보안(Security), 부분 장애(Partial Failure) 허용 등.

---

### 3. 분산 시스템의 정의 ★

> "A collection of independent computers that appears to its users as a single coherent system."
> (사용자에게 하나의 일치된 시스템처럼 보이는 독립적인 컴퓨터들의 모음)

- **① 하드웨어적 측면: Independent (독립적 / 자율적)**
    - **Autonomous**: 각 컴퓨터가 고유의 로컬 메모리와 **독자적인 운영체제(OS)**를 가짐.
    - **No Shared Memory & No Shared Clock**: 공유 메모리가 없고, CPU 타이머(클럭)도 서로 다름.
    - **Message Passing**: 공유 메모리가 없으므로 프로세스 간 통신은 반드시 메시지 패싱을 통해 수행 (시스템 구축의 난이도 상승 요인).
- **② 소프트웨어적 측면: Single Coherent System (단일 시스템 이미지)**
    - 내부는 여러 대의 독립된 컴퓨터지만, 사용자나 어플리케이션 입장에서는 마치 하나의 컴퓨터(**Single System Image**)처럼 보이게 함.

---

### 4. 하드웨어 관점에서의 커플링 (Coupling)

- **컴퓨터의 정의**: CPU와 메모리가 존재하여 데이터를 처리하고 저장하는 기기 (폰 노이만 구조).

- **① Tightly Coupled (강결합) = Multiprocessor System**
    - **특징**: 공유 메모리(Shared Memory)를 사용함.
    - **통신 속도**: 프로세스 간 통신(Inter-process)과 CPU-메모리 간 통신(Intra-process) 속도가 비슷할 정도로 매우 빠름.
    - **구조**:
        - **Bus-based**: 메인보드에 여러 CPU와 메모리를 꽂아 버스로 통신.
        - **Switch-based**: 크로스바(Crossbar) 스위치 사용. 현재는 하이어라키컬(계층적) 스위치 방식으로 정착됨.

- **② Loosely Coupled (약결합) = Multicomputer System**
    - **특징**: 각자 독립된 프라이빗 메모리(Private Memory)를 가진 컴퓨터들이 네트워크로 연결됨.
    - **통신 속도**: 내부 통신보다 네트워크 외부 통신 속도가 상대적으로 느림 (최근 Zero-copy 기술 등으로 격차 감소 중).
    - **구조**:
        - **Bus-based**: 과거 T자 스위치 등을 이용한 버스 연결 방식 (병목 및 충돌 문제 존재).
        - **Switch-based**: 현재 대다수의 랩실 등에서 사용하는 스위치 기반 연결 방식.

---

### 5. 소프트웨어 관점에서의 커플링과 OS의 4가지 진화 단계

- **① Centralized OS (60~70년대)**: 단일 CPU와 메모리를 관리하는 초창기 OS. 부족한 자원을 효율적으로 쓰기 위한 **가상 머신(VM)** 개념 등장.
- **② Network OS (NOS) (80년대)**: LAN/WAN 상의 이기종(Heterogeneous) 컴퓨터를 위한 Loosely Coupled OS. 리소스 공유와 상호 운용성(Interoperability)이 목표.
- **③ Distributed OS (DOS) (90년대)**: 기가비트 스위치 등장으로 여러 대를 하나의 컴퓨터처럼 묶으려는 시도.
    - **사례**: 아메바(Amoeba) OS (중앙 통제 방식, Single Name Space 지원).
    - **실패 원인**: 유연성 부족(Inflexible). 다른 OS를 사용할 수 없어 상업적으로 외면받음.
- **④ Middleware (2000년대 ~ 현재)**: Network OS 위에 계층(Layer)을 추가하여 Distributed OS의 투명성을 구현.
    - **특징**: 기존 OS를 유지하면서 어플리케이션을 위한 표준 API 제공 (예: 하둡의 YARN/MapReduce).

### 6. 미들웨어의 핵심 역할: 투명성(Transparency) 지원

미들웨어는 시스템이 분산되어 있다는 사실을 사용자에게 숨김.

- **Access(접근)**: 데이터 표현 방식(XML, JSON 등)과 리소스 접근 방법의 차이를 숨김.
- **Location(위치)**: 리소스의 물리적 위치를 숨김.
- **Migration & Relocation(이주 및 재배치)**: 서비스 중(Migration) 혹은 정지 후(Relocation) 프로세스를 다른 서버로 옮기는 것을 숨김.
- **Replication(복제)**: 성능 향상 및 신뢰성을 위해 동일 리소스를 복제하여 관리함을 숨김.
- **Concurrency(동시성)**: 여러 프로세스가 동시에 자원을 사용할 때의 Race Condition 및 Deadlock 문제를 해결.
- **Failure(장애 허용)**: 부분 장애(Partial Failure)가 발생해도 전체 시스템이 다운되지 않도록 방어.
- **Persistence(영속성)**: 휘발성 메모리 데이터를 비휘발성 저장 장치에 저장하여 영구 보존.

---

### 7. 2013년 이후의 현대 분산 시스템 트렌드

- **2013년의 분기점**: 모바일 기기 숫자가 PC를 추월하며 클라우드(Cloud)가 비즈니스 기반이 됨.
- **빅데이터와 AI**: 모바일 데이터 축적 -> 빅데이터 분석 -> 클라우드 집중 -> GPU 병렬 처리 기반 AI 발전.
- **IoT(사물인터넷)**: 모든 사물이 네트워크로 연결되는 환경 (예: 무인 자동차 통신).
- **현대 기술 아키텍처**:
    - **서버 사이드**: 쿠버네티스(k8s), 오픈스택(OpenStack) 등 가상화/오케스트레이션 기술.
    - **보안 및 기타**: 블록체인, 디지털 트윈, 엣지 컴퓨팅, 이벤트 드리븐(Event-driven) 아키텍처.
- **미들웨어 사례**:
    - **메신저**: 카톡, 인스타그램 DM 등은 하단의 공통 미들웨어 위에 다양한 비즈니스 로직을 구축함.

### 📝 시험 예상 문제 및 해설

#### Q1. 분산 시스템의 정의를 기술하고, 하드웨어 및 소프트웨어적 측면의 특징을 설명하시오.
- **해설**: 
    - **정의**: 사용자에게 하나의 일치된 시스템처럼 보이는 독립적인 컴퓨터들의 모음 (A collection of independent computers that appears to its users as a single coherent system).
    - **하드웨어 측면**: 각 노드는 **자율적(Autonomous)**이며, 독자적인 OS와 로컬 메모리를 가짐. 공유 메모리와 공유 클럭이 없으므로 통신은 **메시지 패싱**을 통해 이루어짐.
    - **소프트웨어 측면**: 사용자나 어플리케이션에게 시스템이 하나로 보이는 **단일 시스템 이미지(Single System Image)**를 제공함.

#### Q2. 미들웨어에서 지원하는 '투명성(Transparency)' 중 Location Transparency와 Failure Transparency의 개념을 예시와 함께 설명하시오.
- **해설**:
    - **Location Transparency**: 사용자가 리소스의 물리적 위치를 알 필요 없이 접근할 수 있게 함. (예: URL만으로 서버 파일 접근)
    - **Failure Transparency**: 시스템의 일부(부품이나 노드)가 고장 나도 사용자는 이를 인지하지 못하고 서비스가 계속 작동함. (예: 클라우드 서버 한 대가 죽어도 전체 서비스는 정상 유지)

#### Q3. Tightly Coupled(강결합)와 Loosely Coupled(약결합) 시스템을 하드웨어 관점에서 비교하시오.
- **해설**:
    - **Tightly Coupled**: **공유 메모리**를 사용하며, 프로세스 간 통신 속도가 CPU-메모리 간 통신 속도만큼 매우 빠름. (예: 멀티프로세서 시스템)
    - **Loosely Coupled**: 각 노드가 **독립된 프라이빗 메모리**를 가지며 네트워크로 연결됨. 통신 속도가 상대적으로 느리나 확장이 용이함. (예: 멀티컴퓨터 시스템, 클러스터)

#### Q4. Distributed OS(DOS)의 상업적 실패 원인과 이를 대체한 Middleware의 특징을 설명하시오.
- **해설**:
    - **실패 원인**: **유연성 부족(Inflexible)**. 모든 노드에 동일한 전용 OS(예: Amoeba)를 설치해야 했기에 범용 OS(윈도우, 리눅스 등)를 쓰고 싶어 하는 실무 환경에서 외면받음.
    - **Middleware의 특징**: 기존의 다양한 **Network OS(NOS) 위에 추가 계층**으로 존재하며, 이기종 환경에서도 단일 시스템 이미지를 제공하고 표준화된 API 프로그래밍 인터페이스를 제공함.

#### Q5. Hadoop 2.0이 1.0과 갖는 차이점과 해결한 문제점은 무엇인가?
- **해설**:
    - **차이점**: 리소스 관리 계층인 **YARN(Yet Another Resource Negotiator)**의 도입.
    - **해결한 문제점**: 1.0의 JobTracker에 집중된 부하(Bottleneck) 및 단일 장애점(SPOF) 문제를 해결하고, MapReduce 외에도 다양한 데이터 처리 엔진이 하둡 위에서 돌아갈 수 있도록 확장성을 확보함.
