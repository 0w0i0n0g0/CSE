## 03. Docker

### 1. 가상화(Virtualization) 및 가상 머신(VM) 아키텍처

도커를 이해하기 위한 선수 지식으로, 가상 머신 기반의 아키텍처 스타일과 가상화 계층에 대한 이해가 필요합니다.

- **가상 머신 아키텍처 스타일**: 시스템을 세 가지 계층으로 구분합니다.
    - 하단: 기존 플랫폼 (Existing Platform)
    - 중단: **가상 머신 (Virtual Machine)** - 기존 플랫폼과 앱 사이를 연결 및 분리(Separates)하는 역할
    - 상단: 애플리케이션 (Application)
- **주요 특징**: 하드웨어나 소프트웨어 플랫폼에 독립적(Independent)으로 작동하게 하며, 보안성, 설치 용이성, 재사용성, 가용성을 높여줍니다. (에뮬레이션 소프트웨어와 유사한 역할 수행)
- **가상화 구현 레벨 (5단계)**:
    1. **ISA(명령어 집합) 레벨**: Bochs, Crusoe, QEMU (바이너리 코드 변환)
    2. **HAL(하드웨어 추상화) 레벨**: VMware, Xen (Hypervisor 기반)
    3. **OS(운영체제) 레벨**: Jail, LXC, **Docker** (도커가 속하는 계층)
    4. **라이브러리 레벨**: WINE, vCUDA
    5. **애플리케이션 레벨**: JVM, MS .NET CLR

- **가상 머신 적용 예시**:
    - **JVM / .NET CLR**: 소스 코드를 중간 언어(Bytecode, IL code)로 변환하여 OS에 독립적으로 실행하게 함.
    - **Android**: 리눅스 커널(C) 위에 자바/코틀린 앱 실행을 위해 Android Runtime(ART) 가상 머신을 얹은 구조.

### 2. 도커(Docker)의 정의와 핵심 개념

도커는 OS 레벨의 가상화를 사용하여 소프트웨어를 '컨테이너(Containers)'라는 표준화된 패키지 형태로 제공합니다.

- **도커(Docker)**: 운영체제 수준의 가상화를 사용하여 컨테이너 내 애플리케이션 배포를 자동화하고 일관된 실행을 보장하는 제품군.
- **도커 컨테이너(Docker Container)**: 코드와 모든 종속성(Dependencies)을 패키징한 소프트웨어의 표준 단위.
- **도커 이미지(Docker Image)**: 애플리케이션 실행에 필요한 모든 것(코드, 런타임, 라이브러리 등)을 포함한 가볍고 독립적이며 실행 가능한 읽기 전용(Read-only) 패키지.
- **물류 컨테이너 비유**: 과거 규격이 제각각이던 화물을 '표준 컨테이너'로 통일하여 물류 혁명을 이룬 것처럼, 소프트웨어도 어떤 환경에서든 동일한 규격으로 실행되도록 캡슐화함.

---

### 3. 도커의 구조와 작동 원리

- **아키텍처**: Infrastructure -> Host OS -> **Docker Engine(Daemon)** -> Isolated Containers (App & Libs)
- **하이퍼바이저 VM과의 차이**: 기존 VM은 무거운 Guest OS를 각각 포함하지만, 도커는 **호스트 OS의 커널을 공유**하므로 매우 가볍고 빠릅니다. (Lightweight)
- **유니온 파일 시스템(Union File System / Copy-on-Write)**:
    - 베이스 이미지는 **공유(Share)**하고, 변경사항(Diffs)만 별도의 쓰기 가능(Writable) 레이어에 저장하여 효율성을 극대화함.
- **컨테이너 실행 과정(What happens when you run?)**:
    1. 이미지가 로컬에 없으면 Docker Hub에서 **Pull**.
    2. 새 컨테이너 생성 및 파일 시스템 할당.
    3. 읽기-쓰기 레이어 마운트.
    4. 네트워크 브리지 인터페이스 및 IP 할당.
    5. 지정된 프로세스 실행 및 출력 캡처.

---

### 4. Dockerfile과 주요 명령어

- **Dockerfile**: 컨테이너를 빌드하기 위한 설계도(스크립트).
```dockerfile
FROM ubuntu:16.04
RUN apt-get update -y && apt-get install -y python-pip
COPY ./requirements.txt /app/requirements.txt
WORKDIR /app
RUN pip install -r requirements.txt
COPY . /app
ENTRYPOINT [ "python" ]
CMD [ "app.py" ]
```

- **핵심 명령어**:
    - `docker build -t [이미지명] .`: 현재 디렉토리의 Dockerfile로 이미지 생성.
    - `docker run -d -p [호스트포트]:[컨테이너포트] [이미지명]`: 컨테이너를 백그라운드에서 실행.
    - `docker ps -a`: 실행 중인 컨테이너 및 전체 목록 확인.
    - `docker pull / push`: 레지스트리에서 이미지를 내려받거나 업로드.

---

### 5. 도커 생태계 (Docker Ecosystem)

- **Docker Hub**: NGINX, MongoDB 등 세계 최대 규모의 컨테이너 이미지 라이브러리 및 공식 이미지 저장소.
- **라이프 사이클**: Base Image **Pull** -> 수정(**Change**) -> **Commit** -> 이미지 생성 -> **Push** (배포).
- **마이크로서비스(MSA) 및 데브옵스(DevOps)**:
    - **MSA**: 거대한 모놀리식 구조를 기능별 독립적 컨테이너로 쪼개어 배포함.
    - **DevOps**: 빌드, 테스트, 릴리즈, 배포 과정을 도커와 쿠버네티스(Kubernetes)를 통해 자동화(CI/CD).

---

### 6. 도커의 가치 (Value Proposition)

- **개발자(Developer)**: "Build Once, Run Anywhere" (환경 불일치 문제 해결)
- **운영자(Operator)**: "Configure Once, Run Anything" (표준화된 배포 체계)
- **NXN 배포 문제 해결**: 다양한 앱(Y축)과 다양한 환경(X축) 사이의 복잡성을 컨테이너 규격 하나로 통일하여 해결.

> ### 🚨 도커의 장단점 및 핵심 평가 요소 (시험 출제 포인트)
> 교수님께서 구조, 개념, 장단점 위주로 시험 문제가 출제될 것임을 강조하셨습니다.

#### 💡 도커의 3대 장점 (Benefits)
1. **프로비저닝 (Provisioning)**: 표준화된 환경을 통해 빠르고 일관된 배달(Delivery) 및 CI/CD 워크플로우 통합 가능.
2. **성능 및 확장성 (Performance)**: Guest OS가 없어 매우 가볍고, 거의 실시간으로 스케일 업(Scale-up) 또는 제거(Tear-down) 등 동적 워크로드 관리가 용이함.
3. **밀도 (Density)**: 동일한 하드웨어 리소스 상에서 기존 하이퍼바이저 방식보다 훨씬 더 많은 수의 워크로드(컨테이너) 구동 가능.

#### 💡 도커의 2대 단점 (Drawbacks)
1. **격리성 감소 (Reduced Isolation)**: OS 커널을 공유하므로 하이퍼바이저 기반 VM보다 완벽한 격리가 어려움. (하나의 컨테이너가 커널에 영향을 주면 전체에 파급 가능성 존재)

### 📝 시험 예상 문제 및 해설

#### Q1. 가상 머신(VM)과 도커 컨테이너(Docker Container)의 구조적 차이점과 그로 인한 도커의 이점을 설명하시오.
- **해설**: 
    - **구조적 차이**: 기존 VM은 하드웨어 위에서 각자 **Guest OS**를 가지는 무거운 구조인 반면, 도커는 호스트 OS의 **커널을 공유**하고 필요한 라이브러리/바이너리만 격리하여 컨테이너로 띄우는 가벼운 구조임.
    - **이점**: 무거운 OS가 없으므로 시스템 리소스를 적게 차지하며, 부팅 속도가 매우 빠르고 이미지 용량이 작아 이식성이 뛰어남.

#### Q2. 도커의 3대 장점(Provisioning, Performance, Density)을 각각 설명하시오.
- **해설**:
    - **Provisioning (프로비저닝)**: 개발-테스트-운영 환경을 통일시켜 소프트웨어 배포(Delivery) 속도를 획기적으로 높이고 CI/CD 파이프라인 통합을 용이하게 함.
    - **Performance (성능)**: Guest OS 부하가 없으므로 네이티브에 가까운 성능을 내며, 비즈니스 요구에 맞춰 실시간으로 컨테이너를 스케일 업/다운하기 용이함.
    - **Density (밀도)**: 동일한 물리적 서버 사양에서 기존 VM보다 훨씬 더 많은 수의 컨테이너를 구동할 수 있어 비용 효율성이 높음.

#### Q3. 도커의 단점인 '격리성 감소'와 '보안성 감소'의 원인과 그 위험성을 기술하시오.
- **해설**:
    - **원인**: 시스템 자원을 완전히 분리하는 하이퍼바이저 방식과 달리, 도커는 호스트 OS의 **커널을 공유**하기 때문임.
    - **위험성**: 특정 컨테이너에서 커널 패닉(Panic)이 발생하거나 악의적인 커널 레벨 침투가 일어날 경우, 호스트 OS 전체와 그 위에서 돌아가는 다른 모든 컨테이너가 동시에 영향을 받을 수 있음.

#### Q4. 도커에서 여러 이미지를 효율적으로 관리하기 위해 사용하는 '유니온 파일 시스템(Union FS)'의 특징을 설명하시오.
- **해설**: 
    - 여러 개의 레이어를 겹쳐서 하나의 파일 시스템처럼 보이게 함. 공통되는 베이스 이미지 레이어는 **공유(Read-only)**하고, 실제 수정된 부분만 새로운 레이어로 쌓으므로 용량을 절약하고 이미지 생성 속도를 높임. (Copy-on-Write 방식 활용)

#### Q5. 도커 컨테이너를 실행(`docker run`)할 때 내부적으로 일어나는 주요 단계 중 3가지만 기재하시오.
- **해설**: (다음 중 3가지 선택)
    1. 로컬에 이미지가 없으면 레지스트리에서 이미지를 **Pull**함.
    2. 격리된 새 컨테이너를 생성하고 파일 시스템을 할당함.
    3. 이미지 위에 읽기-쓰기 가능한 **Writable Layer**를 마운트함.
    4. 네트워크 인터페이스와 **IP 주소**를 할당함.
    5. 지정된 프로세스(Application)를 실행함.
